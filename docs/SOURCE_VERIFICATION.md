# Source Verification Workflow

## Source hierarchy
Usually prefer official issuer terms and conditions, fee schedules/rewards guides/change notices, official product pages/FAQs, official network/program documentation where relevant, then secondary sources for discovery only. A dated official PDF may be more authoritative than marketing copy for exclusions.

## Evidence fields
Title, issuer/publisher, canonical URL/document ID, type, publication/retrieval/effective dates, content hash, page/heading, short excerpt, reviewer, status, and licensing status.

## Workflow
1. Resolve exact variant and market.
2. Find authoritative current terms.
3. Identify each material claim.
4. Capture source locator and dates.
5. Draft typed rule and test cases.
6. Attach evidence.
7. Run schema/conflict validation.
8. Independent review.
9. Atomic publication.
10. Audit event and review date.

## Freshness/conflicts
Define freshness by source type and risk. A source change creates a review candidate, not an automatic rule change. If sources conflict, record both and resolve by authority/effective date. Until resolved, mark the rule conflicting or unavailable for confident calculation.

## Rights and access
Check terms, copyright, and redistribution permissions. Store only permitted/necessary excerpts. Do not bypass authentication, rate limits, or access controls.
