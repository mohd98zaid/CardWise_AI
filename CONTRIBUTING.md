# Contributing

## Rules
Keep calculations deterministic and isolated from AI. Use Decimal. Test every rule type and boundary. Never hard-code live card terms in business logic. Do not publish material rule changes without evidence/review. Treat unknown values explicitly. Never add sensitive data to fixtures/logs. Pin dependencies and document important choices.

## Pull request checklist
- [ ] Requirements and edge cases described.
- [ ] Tests added/updated.
- [ ] Rule schemas/fixtures validated.
- [ ] Authorization reviewed.
- [ ] No secrets/private data.
- [ ] Docs updated.
- [ ] Migration/rollback impact described.
- [ ] Accessibility considered.

## Rule data contributions
Include exact variant, authoritative source, locator, effective dates, typed parameters, test cases, and reviewer notes. Secondary sources alone are not enough for a material current rule.
